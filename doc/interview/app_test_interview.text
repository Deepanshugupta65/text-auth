### Testing implemented in my FastAPI project

I used **pytest and FastAPI TestClient** to automate API testing instead of relying only on manual Postman/Swagger testing.

I created a separate **test PostgreSQL database** so that test data does not affect the actual application database. I also used **pytest fixtures** to reset the test database for each test and provide a reusable database session.

I tested the **authentication flow**, including:

* User registration
* Duplicate email validation
* Login with correct password
* Login with incorrect password
* JWT token generation
* Protected API access with a valid JWT
* Requests with missing or invalid JWT
* Logout endpoint

I also tested **task APIs**, including:

* Creating tasks
* Retrieving tasks
* Updating tasks
* Deleting tasks
* Searching tasks
* Filtering completed tasks
* Pagination
* 404 handling for non-existing tasks

For **authorization**, I verified that a normal user can access their own tasks but cannot modify another user's task, while an admin can manage tasks belonging to other users.

I used assertions to verify **HTTP status codes, response data, authentication tokens, user roles, ownership, and expected error messages**.

The testing flow was:

Client → FastAPI Router → Schema Validation → Authentication/Authorization → Database → Response → Assertions
